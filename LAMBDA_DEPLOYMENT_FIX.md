# Lambda Deployment Issue - IAM Roles Not Created

## Problem
When deploying CloudFormation templates generated by the AI, Lambda functions were failing with:
```
Template error: instance of Fn::GetAtt references undefined resource <FunctionName>Role
```

## Root Cause
The CloudFormation generator was creating Lambda functions that referenced IAM roles (e.g., `CreateTodoRole`), but those IAM roles were never created in the template.

## Solution Implemented
Modified `backend/src/lambdas/deployment/generate-cloudformation.ts` to automatically create IAM roles for Lambda functions:

1. **Check by CloudFormation resource type** instead of service type:
   ```typescript
   if (cfnType === 'AWS::Lambda::Function') {
     // Create IAM role automatically
   }
   ```

2. **Create role before Lambda function**:
   - Role logical ID: `${lambdaLogicalId}Role`
   - Includes AWSLambdaBasicExecutionRole managed policy
   - Proper AssumeRole policy for lambda.amazonaws.com

## Critical Lesson: TypeScript Compilation Required

**IMPORTANT**: CDK packages BOTH `.ts` and `.js` files, but Node.js Lambda runtime executes the `.js` files!

### The Issue
- We modified the `.ts` file
- Deployed with `cdk deploy`
- But the old `.js` file was still being executed
- Changes didn't take effect until we deleted `.js` files and redeployed

### Solution for Future Development

**Always compile TypeScript before deploying:**

```bash
# Option 1: Delete compiled files to force recompilation
cd backend
rm -rf src/**/*.js src/**/*.d.ts
npx cdk deploy

# Option 2: Run explicit build (but tests might fail)
cd backend
npm run build
npx cdk deploy

# Option 3: Use esbuild bundling (recommended for production)
# Update CDK stack to use NodejsFunction with bundling
```

### Best Practice Going Forward

1. **Delete `.js` files before deployment** if you've modified `.ts` files
2. **Use `NodejsFunction`** construct instead of `Function` - it bundles automatically
3. **Add a pre-deploy hook** to clean compiled files
4. **Enable source maps** for better debugging

## Files Modified
- `backend/src/lambdas/deployment/generate-cloudformation.ts`
  - Added automatic IAM role creation for Lambda functions
  - Changed condition from `service.type === 'Lambda'` to `cfnType === 'AWS::Lambda::Function'`
  - Added detailed logging for debugging

## Testing
After the fix, generated templates now include:
- Lambda function resources
- Corresponding IAM role resources (with `Role` suffix)
- Proper Fn::GetAtt references that resolve correctly

## Prevention
Consider updating the CDK stack to use `NodejsFunction` which automatically bundles and compiles:

```typescript
import { NodejsFunction } from 'aws-cdk-lib/aws-lambda-nodejs';

const myLambda = new NodejsFunction(this, 'MyFunction', {
  entry: 'src/lambdas/my-function.ts', // Entry point
  handler: 'handler',
  // Automatic TypeScript compilation and bundling
});
```

This eliminates the `.ts` vs `.js` issue entirely.
